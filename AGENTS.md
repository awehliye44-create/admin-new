# Architecture rules

- Trip-specific preset configuration must require the trip's rider, a server-verified admin, or a JWT-linked driver with an unexpired pending `ride_offers` row; always use the trip's stored service area and existing negotiation gates to prevent unrelated access and generic-offer fallback.- Staff access resolves through `staff_profiles.role_id` → `staff_roles_catalog`, and page/action permissions are keyed by `role_id`; `staff_profiles.role` is a trigger-derived access level kept only for legacy role-name checks. Why: owner-created roles must drive every permission check from a single source.
- Super Admin is the single `staff_profiles.is_owner` account; staff/role/permission management (`roles_permissions.*` actions and the `roles` page) is owner-only and non-delegable, enforced in `staff_has_action`/`staff_has_page_access` and table triggers. Why: no other role, including Admin, may manage staff access.
- Driver tap location proof (Arrived, No-show, Trip ended) is captured only by the `trips` AFTER UPDATE trigger into immutable `trip_action_location_evidence`, never by edge functions or the client. Why: one capture point covers every writer path and stays live without backend function deploys.
- `admin_page_select`/`admin_page_mutate` never splice caller values into SQL text: filters and patch values are bound as EXECUTE parameters and cast per target column type via `_admin_page_bind_value`/`_admin_page_col_type` (json/jsonb kept verbatim, arrays via ARRAY(...)); only allowlisted identifiers are formatted in. Why: removes SQL-injection surface from the SECURITY DEFINER admin RPCs while keeping jsonb and integer[] fields saving correctly.
- `supabase/functions/_shared/` holds only code imported by two or more edge functions; single-function helpers live in `<function>/lib/`, backend tests and test-only helpers in `supabase/tests/_shared/`. Why: every function upload includes all of `_shared/`, capped at ~4.5 MB.
