## Confirmed root cause

`register-customer-live-activity-token` selected `device_id, server_device_id` from `customer_active_devices`.

**`server_device_id` does not exist** on that table. PostgREST rejected the select → every register returned `DEVICE_LOOKUP_FAILED` → tokens never persisted → publish could never fan out ActivityKit updates.

The prior unique-index / upsert fix was necessary but insufficient: registration never reached the upsert.

## Secondary defect (screenshot contradiction)

Finding copy used `progress_step_index: 0`, which lights the first milestone label **“Driver assigned”** while the title still says **“Finding your driver”**. Finding must use `-1` (no milestones reached).

## Identity / hydrate

Terminal projection cleared driver/vehicle (expected on cancel). Mid-trip identity cannot be read from the overwritten row; hydrate path is deployed and covered by SSOT tests. Without ActivityKit tokens, even a correct projection could not update the Lock Screen while backgrounded.

## Fixes

1. Register Edge: select `device_id` only; warn on non-authoritative device.
2. Projection + Customer JS: finding `progress_step_index = -1`; heading/arrived/in-progress title parity.
3. Customer JS: retry failed token register + flush on foreground.
4. Native (next rebuild): re-emit last ActivityKit tokens when JS re-subscribes.
